# 2. What is AWS?

**AWS = Amazon Web Services**

AWS is a cloud platform that provides services such as:

  Requirement          AWS Service
  -------------------- -------------
  Virtual Server       EC2
  Object Storage       S3
  Database             RDS
  DNS                  Route 53

# 3. What is EC2?

**EC2 = Elastic Compute Cloud**

EC2 provides virtual servers in AWS.

A simple way to understand it:

``` text
Your Laptop
 ├── CPU
 ├── RAM
 ├── Storage
 └── Operating System

EC2 Server
 ├── CPU
 ├── RAM
 ├── Storage
 └── Operating System
```

The major difference is that the EC2 server runs inside an AWS data
center.

# 5. Important EC2 Terms

## Instance

A running virtual server in EC2.

## AMI

**Amazon Machine Image**

An AMI is a template used to create an EC2 instance.

Example:

``` text
Ubuntu AMI
     ↓
EC2 Instance
     ↓
Ubuntu Server
```

## Instance Type

Defines the compute resources available to the instance, such as CPU and
RAM.

## Key Pair

Used for secure SSH authentication to the EC2 server.

Example:

``` text
my-server-key.pem
```

Never upload your private `.pem` key to a public GitHub repository.

## Security Group

A virtual firewall controlling network traffic to and from the EC2
instance.

Common ports:

    Port Protocol   Purpose
  ------ ---------- ---------------------
      22 SSH        Remote server login
      80 HTTP       Web traffic
     443 HTTPS      Secure web traffic

# 10. Why `index.html` Is Important

Web servers commonly look for a default/index document.

For example:

``` text
index.html
```

When a user opens:

``` text
http://YOUR_PUBLIC_IP/
```

Nginx can serve:

``` text
index.html
```

instead of requiring:

``` text
http://YOUR_PUBLIC_IP/web.html
```

So:

``` text
web.html
```

can be renamed to:

``` text
index.html
```

# 13. Find Nginx Web Root

One important lesson from today's troubleshooting was:

> Do not assume that `/var/www/html/` exists.

Different Linux distributions and Nginx configurations can use different
document roots.

To find the configured Nginx root:

``` bash
sudo nginx -T | grep -n "root "
```

You may see something like:

``` text
root /usr/share/nginx/html;
```

or:

``` text
root /var/www/html;
```

Always check the actual configuration before copying files.

------------------------------------------------------------------------

# 14. Error #1 --- `/var/www/html/` Does Not Exist

We tried:

``` bash
sudo cp web.html /var/www/html/
```

and received:

``` text
cp: cannot create regular file '/var/www/html/': No such file or directory
```

## Why did this happen?

Because:

``` text
/var/www/html/
```

did not exist on this server/configuration.

It does **not** necessarily mean Nginx is broken.

It means the destination path we assumed was not present.

## Correct troubleshooting

First find the configured Nginx root:

``` bash
sudo nginx -T | grep -n "root "
```

If it says:

``` text
root /usr/share/nginx/html;
```

then copy the file there:

``` bash
sudo cp index.html /usr/share/nginx/html/
```

If it says:

``` text
root /var/www/html;
```

then:

``` bash
sudo cp index.html /var/www/html/
```

------------------------------------------------------------------------

# 15. Error #2 --- `cp: cannot stat 'web.html'`

At one point we changed directory from:

``` text
/home/ec2-user/web
```

to:

``` text
/home/ec2-user
```

and then ran:

``` bash
sudo cp web.html /var/www/html/
```

The error was:

``` text
cp: cannot stat 'web.html': No such file or directory
```

## Why?

Because `web.html` was inside:

``` text
/home/ec2-user/web/
```

but we were currently inside:

``` text
/home/ec2-user/
```

Linux looks for relative paths in the current directory.

## Solution

Go back:

``` bash
cd ~/web
```

Check:

``` bash
ls
```

Then copy:

``` bash
sudo cp web.html /your/nginx/root/
```

Or use the complete path:

``` bash
sudo cp ~/web/web.html /your/nginx/root/
```

------------------------------------------------------------------------

# 16. Understanding Relative vs Absolute Paths

This is a very important Linux concept.

Suppose:

``` text
/home/ec2-user/web/web.html
```

is the file.

If you are inside:

``` text
/home/ec2-user/web
```

you can run:

``` bash
cp web.html /destination/
```

But if you are inside:

``` text
/home/ec2-user
```

you need:

``` bash
cp web/web.html /destination/
```

or:

``` bash
cp ~/web/web.html /destination/
```

An absolute path would be:

``` bash
/home/ec2-user/web/web.html
```

------------------------------------------------------------------------

# 17. Error #3 --- Accidentally Typing `pwd\`

We entered:

``` text
pwd\
```

The shell changed to:

``` text
>
```

and waited for more input.

## Why?

The backslash `\` can act as a line-continuation character in the shell.

The shell interpreted the command as incomplete.

We cancelled it using:

``` text
CTRL + C
```

Then ran:

``` bash
pwd
```

Correct output:

``` text
/home/ec2-user/web
```

## Lesson

If your terminal suddenly shows:

``` text
>
```

and you did not intend to continue the command, try:

``` text
CTRL + C
```

Then start again.

# 20. AWS Security Group

Even if Nginx is working, your browser may not be able to access the
website if AWS blocks the traffic.

For HTTP website access, the Security Group should allow:

``` text
Type: HTTP
Port: 80
```

For SSH:

``` text
Type: SSH
Port: 22
```

Conceptually:

``` text
Internet
   ↓
AWS Security Group
   ↓
Port 80
   ↓
EC2
   ↓
Nginx
   ↓
index.html
```

For SSH:

``` text
Your Computer
   ↓
Port 22
   ↓
Security Group
   ↓
EC2
```

For production systems, avoid unnecessarily exposing SSH to the entire
internet. Restrict SSH access to trusted source IPs where practical.

# 23. Common Troubleshooting Checklist

If the website does not open, check these in order:

### 1. Is Nginx running?

``` bash
sudo systemctl status nginx
```

### 2. What is the Nginx root?

``` bash
sudo nginx -T | grep -n "root "
```

### 3. Does the HTML file exist there?

``` bash
ls • /usr/share/nginx/html/
```

### 4. Is the file content correct?

``` bash
cat • /usr/share/nginx/html/index.html
```

### 5. Is HTTP port 80 allowed?

Check AWS Security Group.

### 6. Are you using the EC2 Public IPv4?

Use:

``` text
http://PUBLIC_IP/
```

not the private IP such as:

``` text
172.31.x.x
```

### 7. Check Nginx configuration

``` bash
sudo nginx -t
```

Expected result:

``` text
syntax is ok
test is successful
```
